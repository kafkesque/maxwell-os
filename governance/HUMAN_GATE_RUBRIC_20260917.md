# G2 — relabel vs retire the 4,054 orphan FORM rows

**File:** `governance/F14_RELABEL_OR_RETIRE_SAMPLE_20260917.csv` — **30 rows**, stratified across all
7 content types and all 4 FORMs.
**Decision it feeds:** are the 4,054 rows that have no source record (F-14) **legitimate knowledge
objects** that deserve a FORM relabel (~4,054 model calls, ~3 h), or **stale residue** that should
be retired?

**What you will see per row:** name, the object's own DEFINITION, its APPLICATION, an excerpt of
its SOURCE_TEXT, its body length, then its currently assigned labels (content_type / FORM / depth /
discipline / status). The text comes first on purpose — read it before you look at the labels, so
the labels cannot anchor your verdict.

## `G2_VERDICT_keep_or_retire` — exactly one of: `keep` | `retire`

| value | means | test to apply |
|---|---|---|
| `keep` | a legitimate knowledge object: the name matches the body, the body states a usable idea in its own right, and it is not a duplicate of another object | *"If this were the only thing we kept, would it teach someone something actionable?"* → yes |
| `retire` | it should not exist in the KB as a knowledge object | the same question → no |

There is no third value. If you are torn, answer the question above; do not invent a middle.

**How the answer is used (this is why a binary is enough):** the 30-row verdict distribution sets
the scope decision — ≥80% `keep` → relabel all 4,054; ≤50% `keep` → retire the class; in between →
segment further before spending calls. **So tally-friendliness matters more than precision.**

## `G2_quality_1to5` — usability of the object as a knowledge unit

**Fill only when the verdict is `keep`. Write `NA` when the verdict is `retire`** (scoring the
quality of something you just said should not exist is a category error, and it would bias the mean).

| score | meaning |
|---|---|
| **5** | reusable **as-is**: a clear trigger + action, or a clear mechanism; self-contained; non-obvious |
| **4** | usable without editing; one element vague or missing (e.g. no failure mode, thin boundary) |
| **3** | the idea is genuinely there but the expression is thin, generic or vague — a reader would have to rewrite it |
| **2** | mostly restates common sense, or so vague that the "idea" cannot be identified |
| **1** | not usable at all — if you scored 1, the verdict should have been `retire`; please go back and change it |

**No safe middle.** Use 3 only for "real idea, weak expression". If you are torn between 4 and 5,
ask: *"would I quote this to someone as-is, in this wording?"*

**How it is used:** the distribution sets the acceptance bar for the certified core (e.g. "keep
quality >= 4"). It is **not** a second verdict — a low score on a `keep` row means "keep, and
improve it later", not "retire".

## `G2_note_codes` — coded, comma-separated, max 2. `OK` if nothing to report.

| code | use when |
|---|---|
| `OK` | valid object, nothing wrong worth recording |
| `FRAGMENT` | mid-sentence, truncated, or a bare fragment/tool output |
| `SUMMARY` | it summarises what some source says ("this chapter discusses...") instead of stating knowledge |
| `META` | it talks about the book/chapter/author rather than about the subject |
| `THIN` | a real but trivial or self-evident idea |
| `EMPTY` | no usable text at all |
| `DUPLICATE:<exact name of the other object>` | the same object exists elsewhere in the KB |
| `MISLABEL:<field>` | the body contradicts ONE assigned label, e.g. `MISLABEL:extraction_type`, `MISLABEL:content_type` |
| `OTHER:<free text>` | anything else — this is the ONLY place free text belongs |

**Write note codes even on `keep` rows.** A `keep` row carrying `MISLABEL:extraction_type` is
exactly the row the relabel is designed to fix — that is *information*, not a contradiction.

**Why codes and not prose:** 30 free-text notes cannot be counted. 30 codes produce a distribution
we can act on immediately — e.g. *"11 of 30 are `FRAGMENT`"* is a quantitative reason to retire the
class rather than spend 3 hours relabelling it.

## `HUMAN_VERDICT` — one lowercase value from `allowed_answer`, exactly as written

| task | question | allowed values |

No prose in this column. If you truly cannot decide, **still give your best value** and express the
doubt with confidence + a note code — never leave it blank, because a blank is indistinguishable
from "not yet done".

## `HUMAN_confidence_0to1` — how sure you are of **your own verdict**

**Not** a rating of any model. It describes the *question*, not the answerer.

| value | meaning |
|---|---|
| **1.0** | certain — the shown text alone decides it |
| **0.8** | confident — minor ambiguity, no real doubt about the verdict |
| **0.6** | leaning — I would bet on it, but a reasonable person could disagree |
| **0.4** | genuinely split — I could argue either way |
| **0.2** | a guess from a weak signal |
| **0.0** | I cannot judge this from the input given |

**How it is used — read this, it changes what you write:**

- Low-confidence rows are **NEVER dropped** from the headline accuracy. Dropping hard rows would
  inflate the judge's score — the identical selection trap that makes the 0.854 discipline number
  unusable (see `governance/CONTEXT_INDEX.md` §9).
- Accuracy is reported **twice**: all rows, and confident-only (>= 0.6). The gap between them is a
  finding in its own right.
- If **more than a third** of a task's rows are below 0.6, that task is declared **ill-posed** and
  must be made deterministic or human-owned. A weak judge is never the answer to an ill-posed task.

So a low confidence is **not** a failure on your part — it is the single most useful signal on the
sheet. Do not round it up to be helpful.

## `HUMAN_note_codes` — coded, comma-separated, max 2. Blank is fine (= decisive).

| code | use when |
|---|---|
| `AMBIG` | the shown input does not determine the answer |
| `TAXONOMY` | my answer is not in the allowed set — the ontology is missing a value |
| `SOURCE` | I would need the underlying source document to decide |
| `MULTI` | more than one answer is defensible |
| `TRUNCATED` | the shown text was cut off before the decisive part |
| `OK` | decided cleanly, nothing to add |

**Why these matter:** frequent `TAXONOMY` on T3 is direct evidence that the 7-way content_type
ontology is incomplete — a governance finding, not a scoring detail. Frequent `TRUNCATED`/`SOURCE`
means the sheet's rendering, not the judge, is the limiting factor.

# Working rules (both gates)

1. **One task at a time, top to bottom.** Do not jump between tasks — task-switching inflates
   self-inconsistency, which pollutes the calibration.
2. **Timebox ~1 minute per row.** If a row takes more than ~3 minutes, *that is the finding*: score
   confidence <= 0.4 and add `AMBIG` or `SOURCE`.
3. **Blind means blind.** No model runs, no looking at prior artifacts, no asking an LLM for a
   second opinion, before the sheet is complete.
4. **Fill `reviewer` / `date`.** An unattributed label is not evidence (R14).
5. **Do not edit the non-human columns.** If a row looks wrong (missing text, mismatched name), add
   `OTHER:row looks broken` rather than fixing it — the sheet is a measurement instrument, and
   editing it destroys the measurement.

# What happens after you finish

G2 → the relabel-vs-retire scope decision, then (if `keep` wins) F-14.
G3 → the two candidate judges are run over the identical 36 rows (~72 calls, ~10 min), accuracy is
computed per task per judge, the winning judge per task is written to
`governance/judge_calibration_20260917.json`, and only then do the ~650 re-verification calls run —
with a verifier chosen by measurement rather than by intuition.

| principle | 8 | 0 | 0 |
| process_template | 4 | 0 | 0 |

So the junk is **already labelled as junk**: every `noise_drop` and `quarantine` row scored 0

Applied to the 4,054 orphans this partitions them into: **3,348 clear relabel** (principle 3,198 +

rates are not. Because an orphan row is already in the KB with its existing `content_type`, the
downside of relabelling a marginal row is small, so no confirmatory sample is required for the main
bucket.
