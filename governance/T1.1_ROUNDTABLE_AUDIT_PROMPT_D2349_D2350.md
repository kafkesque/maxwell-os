## 1. Context — what you are auditing

Maxwell OS is a **local-first, sovereign knowledge-extraction pipeline** that converts a
corpus of technical books (EPUB/PDF) into a verified knowledge base of *fact-blocks* (FBs).

**Pipeline (stage 3 removed by D2120):**
`0 convert → 0.5 metadata → 1 chunk → 1.3 prefilter → 1.5 embed+cluster → 2 extract → 4 merge/classify → 5 verify → 6 commit`

**Models (R5 cross-family):** S2 generator `Qwen3-Coder-30B-A3B-Instruct-MLX-4bit`; S4
classifier `gpt-oss-20b-MXFP4-Q8`; S2 probe `Phi-4-mini-instruct-8bit`; S5 verifier
`DeBERTa-v3-large` (NLI); embeddings `bge-m3` (Ollama, 1024-dim).

**Iron rules to weigh against:** $0 marginal cost (all local, C1); data sovereign (C3); no
vendor lock-in (C2/C4); temp=0.0 (R7); generator≠verifier (R5); every persistent object
stamped schema_version/gen_model/pipeline_commit (R14); NEVER hardcode (C12); no silent
errors — log AND raise (C16); crash-safe writes tempfile→fsync→os.replace (C6); no dead
code (C19); no magic numbers (C20); swappable infra behind protocols (C21).

**Canary state:** the T1.1 canary ran green (25K segments → S1.5 2255 clusters/207
convergent → S2 280 FBs → S4 279 FBs → S5 239 PASS/40 QUARANTINE → S6 279 committed).
A deep audit then found **identity drift** and **taxonomy misclassification**, now fixed:

### Fix A — D2349: field taxonomy (body / classification / metadata)
`config/content_types.yaml` `core_body` had drifted to include non-body fields. Now three
orthogonal buckets:
- **core_body** (readable knowledge): `name, definition, mechanism, boundary, consequence, elaboration, jargon` — `jargon` renders AFTER `elaboration`.
- **classification** (labels/flags): `content_type` (functional role), `extraction_type` (epistemic form), `is_summary` (gate flag), `domains, discipline, depth, evidence` (flag `cited|axiomatic`), `domains_raw, discipline_raw`.
- **metadata**: `stamps` (R14), `provenance` (`source_books, source_clusters, source_segments, evidence_passages`), `discovery` (`keywords` — search/retrieval labels), `versioning`, `runtime`.

### Fix B — D2350: S4 identity/provenance integrity
`pipeline/stage4_merge.py` had three drift bugs:
1. **fb_id drift** — re-hashed `make_hash_id(name, definition)` AFTER title-casing → 73/279
   FBs would change identity between S2→S4. Now preserves S2's fb_id.
2. **source_clusters semantic drift** — used fb_id as `cluster_id`, overwriting the real
   cluster id (`cluster_48_s1_sub1`). Now uses `fb.get("source_cluster")`.
3. **name-collision pollution** — appended raw 64-char hash `(Cluster <hash>)`. Now a short
   numeric suffix `(2)`, `(3)`, ….

## 2. Your mandate — the failure-mode checklist

Audit for **any** of the following. For each finding state severity (`BLOCKER` / `HIGH` /
`MEDIUM` / `LOW` / `INFO`) and the specific file/line/decision implicated.

1. **Hidden failure** — code paths that fail silently or produce wrong output without erroring.
2. **Error / crash** — inputs, edge cases, or sequences that raise uncaught exceptions.
3. **Leak** — memory, file-handle, connection, or data leak.
4. **Contamination** — stale state, cross-run bleed (run_id/checkpoint caching), prior-run data
   polluting a new run.
5. **Identity/provenance drift** — any field whose value silently changes across stages
   (the fb_id class of bug). Check every `*_id` and `source_*` field end-to-end.
6. **Taxonomy drift** — any field placed in the wrong bucket (body vs classification vs
   metadata). Check `core_body`, `classification`, `metadata`, and per-type `extension_fields`.
7. **Missing parts** — schema fields declared in `config/content_types.yaml` but not emitted,
   serialized, or persisted by the stage that owns them.
8. **Truncation** — any stage that drops or slices a field it should pass through unchanged.
9. **Dead code / magic numbers / hardcoded values** — C12/C19/C20 violations.

## 3. Specific questions — answer each with code evidence (file:line), NOT inference

1. **Jargon survival:** Trace `jargon` from S4 generation → S5 (`vfb = dict(fb)`) → S6
   (`_safe_str(fb.get("jargon"))`) → SQLite. Confirm it is NOT dropped, re-serialized into
   the wrong field, or truncated. Is `jargon` correctly classified as **body** (after
   `elaboration`) and NOT as metadata/classification?
2. **Keywords survival & home:** Confirm `keywords` flows S4 → S5 → S6 → SQLite (`keywords`
   column) and is now classified as `metadata.discovery`. Any downstream that still renders
   it as body content?
3. **fb_id stability (D2350):** Is `fb_id` fixed at extraction (S2) and never recomputed
   downstream? Search for ALL `make_hash_id(` call sites and confirm none run after any
   string normalization.
4. **source_clusters correctness (D2350):** Does `load_stage2_clusters()` now emit the REAL
   cluster id (`cluster_N_s1_subM` / `singleton_*`), and does `source_clusters` in S4/DB
   carry that id (not an fb_id)?
5. **evidence vs evidence_passages:** Is `evidence` (flag `cited|axiomatic`) kept in
   `classification` and `evidence_passages` (verbatim quotes) kept in `metadata.provenance`?
   Any code that writes verbatim text into the `evidence` flag, or the flag into passages?
6. **BUG-106 (S2 checkpoint corruption):** `stage2_extract.py` writes the checkpoint as JSONL,
   but a second path (line ~685) uses `json.dumps(..., indent=2)`. Identify every write to
   `STAGE2_CHECKPOINT` and confirm whether the pretty-print path can reach the checkpoint.
7. **BUG-107 (single-source leak):** Two FBs (`Hybrid Sorting Algorithm`, `Price Reduction
   Profit Maximization`) are single-source yet committed under `--only-convergent`. Trace the
   S2 split-probe k-means path — can a sub-cluster split drop below the ≥2-source bar and
   still be extracted?
8. **Classification ontology:** Are `content_type` (role) and `extraction_type` (epistemic
   form) still treated as orthogonal axes (D2323), or has any stage conflated them?
9. **Parallelism (S4):** S4 batch classification is currently SEQUENTIAL. If parallelism is
   added (`ThreadPoolExecutor`), what ordering/aggregation guarantees are required so
   checkpoint writes stay deterministic and classification results stay in order?
