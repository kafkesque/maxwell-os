slots. D-277 ruled that this measures **pipeline failure, not slot badness** — so the
first move is to **re-derive** each weak slot's definition and give it a mandatory

## What each repaired slot now carries

Every RE-DERIVE slot has:

1. **`definition`** — a discriminating ≤4-sentence definition (what the slot IS).
2. **`include`** — 3 concrete must-map positives (content that MUST land here).
3. **`exclude`** — 2-3 must-NOT-map negatives, each annotated with the sibling slot it
   should map to instead. This is the OntoClean boundary: it turns prose into a
   testable rule.

The two `BOUND`-only slots (design thinking, organizational theory) get the same three
fields but no re-derive — their stored errors reflect the old alias-map discarding, not
a broken definition, so the repair is "force human review on write", not "rewrite".

## D-282 correction (2026-09-20) — depth is not the role discriminator

The first draft of `quarantine` / `process_template` used "a filter across 3+ domains"
as the principle-role boundary. That was a CONFLATION: "3+ domains" is the
**universal-depth** threshold (the `depth` axis), not the principle-**role** criterion
(`content_type` axis). A `domain`-depth (1-2 domains) or `specialized`-depth (1 narrow
domain) principle is still a principle — `schemas.py` states "depth is NOT domain count".

Corrected (D-282): the principle role is **"a self-contained transferable rule you
KNOW/APPLY at any scope"**; scope is the separate `depth` axis and never demotes a
principle into quarantine. The `quarantine.include` no longer treats a single-domain
fact as quarantine by default (a single-domain RULE is a principle; a single-domain
FACT with no reusable rule is the quarantine case).
